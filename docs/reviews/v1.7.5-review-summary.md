## 二、总体结论

v1.7.5 是一个**工程纪律良好但有明确漏网硬伤**的版本。服务层（原子写、退避重试、幂等迁移、事故注释）与前端（Sigma 资源全量销毁、XSS 面封闭、设计 token 化彻底）都高于同类个人项目水准；README 宣称的七项能力全部在代码中兑现，规格实现率约 90%。但存在一个 v1.7.5「19/19 条修复」漏网的**真实认证 bug**，以及双 UI 栈并存、GUI 线程阻塞 IO 两类结构性负债。

## 三、必须立即修复的问题（P0）

### P0-1　`fetcher.py:52` Git Basic 认证头 f-string 错误（已人工复核属实）

```python
raw = f"x-access-token:{token...-8")
```

**这不是脱敏**——`{token...-8` 在 f-string 中被解析为表达式 `token` 后跟字面量 `...-8"`，base64 编码后的凭据包含错误内容，**配置 github_token 后 Git 克隆/查版本必然认证失败**（公司分机场景，恰是该函数注释强调要支持的通道）。该行自 baseline（2026-09-20）即存在，v1.7.5 的 19 条审查修复未覆盖，说明此路径无测试。

**修复**：改为 `f"x-access-token:{token}"`，并补一个断言 header base64 内容的单元测试。

### P0-2　GUI 线程阻塞 IO（memory_view.py 多处）

`batch_ai`（461-468）在 GUI 线程串行执行「每条最长 60s 的 httpx 调用」；`open_inbox`/`admit_one`/`discard_all`/`ai_fill`/`copy_duty`/`show_index`/`refresh_sync`（501-558、329、414-424）同样绕过已有的 `RequestScope`/`jobs` 后台通道。记忆库一大，用户可感知卡死。

**修复**：全部收敛到 `self.scope.call(...)` / `self.jobs.submit(...)`（同文件 `_refresh_now` 已是正确范式，属于套用既有模式，不是新发明）。

### P0-3　Web 亮色主题 `--ink-3` 对比度 3.9:1 不达 WCAG AA

`styles.css:52` `rgba(0,10,30,0.52)` 用于 meta/计数/占位文字，常与 9-11px 小字叠加。

**修复**：透明度 0.52→0.60（约 4.7:1 过 AA），一行变量改动全站受益。
