## 缺失或部分实现的需求

1. **「不做富文本/不做实时自动保存」已守住，但「导出记忆」未做**——02 §八.4 只要求"若做记忆导出按钮需显式启用"，规格本身不要求导出，故不算缺失。
2. **冲突副本隔离的人工裁决提示**（02 §2.2："notes\ 条目冲突副本 → 移入 trash 并**在界面对账结果中提示人工裁决**"）：代码有 `memory.py:424-426` `is_conflict_name` 与 recovery 的 `resolved_conflicts` 计数（`recovery.py:377`），但原生界面未见专门的"待人工裁决"呈现入口，仅状态栏/对账结果数字。属**部分实现**。
3. **「指定技能提示词」沿用**（01 §2.2.3、02 §四）：`memory_facade.py:139-143` 保留了 `skill_install_prompt`/`library_prompt`；但原生技能详情对话框（`skill_view.py:285-335` 的动作区）未见显式的「复制指定技能提示词/安装提示词」按钮，需用户走记忆/库级提示词。v1.4.0 方案称"复制现有注入提示词"已接入，单技能提示词在原生 UI 中的可见入口存疑——**部分实现/入口弱化**。
4. **README 宣称的"附 2-3 个平台的具体位置截图"**（02 §四 README 使用指引）：README §快速开始仅有文字说明，docs/images 只有三张产品截图，无 AGENTS.md/CLAUDE.md 配置位置截图。**文档层缺口**。

## 实现与规格不符之处

1. **接口层形态整体迁移：pywebview/Vue3 SPA → PySide6 原生壳**。02 §一规定"Vue3 SPA（pywebview/WebView2 壳）│ CLI │ REST API（FastAPI, 127.0.0.1）"、"技术栈不动：Python 3.11+ / FastAPI / pywebview / Vue3 / PyInstaller onefile"。当前：
   - 交付主线是 `src/mshub/native/`（PySide6 QMainWindow，`native/main_window.py`），打包为 PyInstaller **onedir**（`packaging/native/123mshub_native.spec`），且发布物拆成程序包+环境包双包（README 31-35 行），与 02 §八"onefile zip 单包"不符；
   - 旧的 web 线（`web/src` Vue3 + `gui.py` pywebview + uvicorn 8766，`gui.py:80-105`）仍在仓内但已非交付主线。
   - **注意：此偏差有明确授权链**——v1.4.0-实施方案.md（"把记忆业务核心接进 PySide6 原生桌面壳……原生代码只新增在 src/mshub/native/"）及 v1.7.x 发布说明。属于**规格文档（v1）滞后于已批准的演进**，而非擅自偏离；但 01/02 两份 v1 文档从未修订回写，后来者只读 v1 文档会得到错误架构预期。
2. **注入提示词模板正文与 02 §四 模板不完全一致**：02 §四 模板无"仓库触发词"一节；`prompts.py:28-31` 新增了「仓库触发词」（出现「总机/mshub/本地仓库/记忆仓库」即读索引）和任务边界判定（:21-22）、易变值不存（:45）。02 §四 注明"实施时以此为基础微调"，且这些增量源自 01 §六 Engramory 吸收条款，属**授权范围内的演化**，但触发词一节超出了 Engramory 条款，无对应规格条目。
3. **配置目录名**：02 §1.1 要求 `%APPDATA%\123mshub\`；`config.py` 的 `default_config_dir()` 需确认实际目录名——v1.6.x 交接文档（docs/v1.6.x-修复交接提示词.md）提到 `%APPDATA%\mshub\web-profile\`，graph_view.py:109 也写 `config_dir = self.facade.config_store.config_dir / "web-profile"`，交接文档自述缓存目录为 `%APPDATA%\mshub`。若实际为 `mshub` 而非 `123mshub`，与 02 §1.1 改名清单第 2 条不符（隔离性影响：与旧 skillrepo 不冲突，但与规格字面不符）。

## 超出规格的行为（scope creep）

1. **记忆批量操作**：`api.py:480-486` `/api/memory/bulk-update`、`/api/memory/bulk-delete`（MemoryService.bulk_update/bulk_delete，`memory_service.py:418-432`）；`memory_view.py:86` 批量改分类/批量标签/批量 AI 补全/批量软删除。01 §2.3 与 02 §五 API 表中均无批量端点（API 表只列单条 CRUD）。属增强，方向合理但规格未授权。
2. **「仓库触发词」协议**（见上节 2）——注入提示词层的新行为，无规格条目。
3. **记忆图谱页整体**（sigma.js 力导向图 + 呼吸动效 + 设置面板）：01/02 两份 v1 规格完全没有图谱；README §记忆图示大段宣传。由 v1.3.x「图谱重构/图谱完善」系列方案引入，属**有演进文档授权的扩展**，但相对原始需求文档是最大的一块 scope creep，且呼吸动效消耗了 v1.6.x 多轮修复（docs/v1.6.x-修复交接提示词.md P0）。
4. **设置页「维护与导入」页的清除配置/解除仓库关联入口**（`settings_view.py:349-368`）：规格未列，属可用性补强。
5. **后台任务面板移到导航栏下半部分、页头统一皇家蓝按钮、Impeccable 设计系统**（v1.7.x）：均为 02 §6.1 布局之外的 UI 演化，有版本文档支撑。

## 总结：最严重的 3 项偏差

1. **v1 规格文档与交付架构脱节（文档失真）**：01/02 规定的技术栈是 pywebview + Vue3 + FastAPI + onefile 单包，v1.7.5 实际交付是 PySide6 原生壳 + onedir + 程序包/环境包双包（README 31-35 行、`packaging/native/123mshub_native.spec`）。虽然 v1.4.0 系列文档授权了这次原生化迁移，但两份 v1 顶层文档从未回写修订，规格轴上的"事实源"已失真。
2. **仓内并存两条 UI 技术线**：`web/src`（Vue3）、`gui.py`（pywebview + uvicorn 8766）、`api.py`（671 行 FastAPI 全家）仍是可运行代码，与 native 线并行。规格的"不做清单"精神是防漂移，双栈并存增加了维护面与审查面，却无任何文档说明 web 线的退役状态。
3. **规格外能力沉淀进产品核心路径**：记忆图谱（含呼吸动效，v1.6.x 耗费多轮修复仍反复）与记忆批量操作 API（`api.py:480-486`）均无 v1 规格条目支撑，其中图谱已成为 README 头号宣传图。扩展本身有版本文档授权，但相对原始需求是最大的 scope 增量，且是历史返工成本最高的部分。
