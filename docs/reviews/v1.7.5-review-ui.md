## 逐项评分与证据

### 1. 排版 —— A-

**做得对**：三套字体栈分工明确且有意图（展示衬线/系统正文/等宽），中文回退链完整（styles.css:16-18）；标题用 `letter-spacing: -0.01em` 收紧、正文 `line-height: 1.55`、`text-wrap: pretty`（styles.css:330）、`font-synthesis: none` 防假斜体假粗（styles.css:34）；`clamp(30px,3vw,40px)` 流式大标题（styles.css:598）；原生侧用 Dream Han Sans 四重字重 + 明确的"标题必须大于按钮"层级修正注释（theme.py:157, main_window.py:146）。

**扣分项**：
- 字号梯 13 档且 9-10px 超小字超过 20 处（styles.css:488, 824, 924, 1327, 1422, 1642…），9px/10px 已是装饰性阅读尺寸，桌面高分屏下可读性堪忧；
- 全大写标签 4 处（styles.css:491, 843, 1645, 5068），其中 `.sidebar-repo > span`（styles.css:488-491）与 `.preview-summary dt`（styles.css:1640-1645）承载的是中文内容（"当前仓库"），`text-transform: uppercase` 对中文无意义，纯装饰残留；
- 无单字斜体强调问题（仅 markdown 渲染器支持斜体语法，styles.css:4112 显式 `font-style: normal`）；
- 行宽：列表/表单界面为主，正文段落短，空状态说明限 `max-width: 460px`（styles.css:1165），无超宽行问题。

### 2. 色彩 —— A

两套色板均完整命名、语义化、双主题同构，且文件头注释明写品牌铁律（styles.css:1-13："无纯黑、无黄色、蓝底只放浅字、糖果色仅限真实状态语义"）。逐项核对 AI 默认套路：

- 米白+陶土橙 `#D97757`：**未命中**。亮色底是米杏 `#F7F5F2` 但品牌色是皇家蓝 `#0156FC`，无任何橙/陶土色（全项目 grep 无 `D97757` 及近似橙，唯一暖色是危险的 `#E3A85B` 与图谱 `#F5C46A`，均为语义状态色）。
- 纯黑+酸性绿：**未命中**。铁律第一条即"无纯黑"（正文 `#000A1E`、暗底 `#030711`，styles.css:49,119），绿只用于安全语义 `#0E6B33/#45D48A`。
- SaaS 圆角卡片+`rgba(0,0,0,.1)` 阴影：**未命中**。亮色阴影全部为蓝色调 `rgba(1,40,150,*)`（styles.css:69-71, 106-113），是少见的"品牌色阴影"做法；`rgba(0,0,0,*)` 仅出现在暗主题（语义正确）。
- `#0B0B0B` 假黑：**未命中**（grep 无；暗底 `#030711` 是带蓝相的设计决策，非默认假黑）。
- 等宽字体小标签：**部分命中**。`.version-label` 等宽（styles.css:1053）显示 commit hash 属正确用途，但 9px/10px 全大写小标签密度偏高（见排版项）。
- 按钮尾巴「→」：**未命中**（全项目 UI 文案 grep 无 `→` 尾巴，仅注释中出现）。

风险点：Web 与原生**两套色板不同源**（米杏 vs 冷灰、透明度阶 vs 实色），同一应用两个壳视觉气质有可见差异；亮色 `--ink-3: rgba(0,10,30,.52)` 在米杏底上对比度仅 **3.9:1**（见第 6 项）。

### 3. 结构 —— A-

- 分隔线、边框全部承载语义：模态头/脚分隔（styles.css:1218, 1255）、侧栏仓库块顶部分隔（styles.css:480）、原生侧栏浮动面板描边（theme.py:112-115）；无纯装饰边框。
- 步骤编号「第 1 步，共 2 步」（AddSkillModal.vue:174）、「快速上手（按顺序三步）」引导（main_window.py 配置提醒）都是真序列内容，编号使用正确；未发现 01/02/03 装饰性编号。
- 原生版还有一次明确的信息层级修复记录：任务面板标题 15px 必须大于"收起/展开"按钮 13px（theme.py:157 注释），说明层级是被当作信息而非装饰管理的。
- 小扣：`MemoryGraph.vue:629` 的 `OBSIDIAN GRAPH VIEW` eyebrow 标签（详见文案项）属于装饰性标签。

### 4. 动效 —— B+

**克制且编排统一**：入场动画只有一组 `rise-in`（0.5s 滑入带 -2px 小过冲），以 60ms 级差编排 5 个区块（styles.css:356-369），正是标准要求的"单一编排入场"；按钮反馈是唯一的悬停签名 `t-nudge`（±2px 轻抖，styles.css:338-343, 650）+ 唯一许可的按下位移 `translateY(1px)`（styles.css:654-657，注释自称"唯一许可"）；时长全部走 `--dur-*` token；主题切换过渡白名单制（styles.css:252-279）；无限动画仅限进度/加载等真实状态指示（`task-slide`、`task-pulse`、`spin`，styles.css:2899, 2980, 3112），无环境性漂浮/呼吸装饰。

**扣分**：`rise-in` 在**每次视图切换**时重放（选择器挂在 `.view-heading` 等常驻类上，非首屏限定），非用户触发的动效频次偏高；`t-nudge` 被复用到标签、chip 等 7 类组件悬停（styles.css:650, 669, 1782, 3585），签名动效略有稀释。reduced-motion 兜底完整（见第 6 项），拉回分数。

### 5. 文案 —— B+

**用户视角命名**：大量实现词已被翻译成人话——「Archive 压缩包（推荐）/Git 浅克隆」解释安装模式（AddSkillModal）、「路线 A · 普通检查：离线、免费、秒出结果 / 路线 B · AI 深度审查：联网、更强、按量计费」（ScanModal.vue:110-117）把技术参数转成决策语言；「本地自研（禁用在线更新）」「ZIP 压缩包（免装 Git）」（settings_view.py:77）。**CTA 说结果**：「保存设置」「开始导入」「确认信任」「收编入库」「丢弃选中」「清除筛选」（EmptyState.vue:16-17、settings_view.py:193、memory_view.py:503），几乎无裸「提交/确定」。

**错误/空状态给方向**：空态三件套完整——「从第一个技能或项目开始 + 说明 + 主按钮」（EmptyState.vue:13-17）；「没有匹配的技能或项目 → 换一个关键词或清除筛选条件」；图谱空态「还没有记忆条目，先在记忆库新建一条。」（MemoryGraph.vue:654）；致命错误「无法连接本地服务 + 重新连接按钮」（App.vue:717-719）；删除确认明确说后果与找回路径（App.vue:583「文件移入仓库的 .meta/trash，避免误操作后无法恢复」）。语气朴素主动，无情绪词、无感叹号轰炸。

**术语一致性（主要扣分）**：

## 文案问题清单

1. **「待确认」vs「需要确认」不一致**：SecurityView.vue:25（统计）与 App.vue:821 / StatusBadge.vue:11 / SkillRow.vue:75（其余全部）——同一安全状态两个名字。
2. **「完全删除」名不符实**：App.vue:584，实际移入 `.meta/trash` 可恢复；应叫「删除」或「移入回收站」，确认文案已正确描述行为，按钮却过度恐吓。
3. **跨层动作名不一**：Web「复制注入提示词」（App.vue:764）↔ 原生「Agent连接提示词」（settings_view.py:41）；同一按钮两种叫法，双语境用户会困惑。
4. **跨层实体名不一**：原生「记忆仓库/技能仓库」（main_window.py、memory_view.py:70）↔ Web「记忆库/技能库」（App.vue:734, 741）。
5. **「OBSIDIAN GRAPH VIEW」eyebrow**（MemoryGraph.vue:629）：实现致敬词暴露给用户，且为纯装饰标签。
6. **「智能主题」含糊**：MemoryView.vue:300,629「补全智能主题」——"智能"是营销词，"主题"实为 AI 生成的描述/摘要，应直说「AI 补全描述」。
7. **toast 信息密度过高**：App.vue:268「注入提示词已复制，粘贴到任意 Agent（对话首条消息或常驻配置）即可接入记忆库与技能库。」——成功提示混入操作教程，4.8s 内读不完；教程应放空态/帮助。
8. **「路线 A/路线 B」编号冗余**（ScanModal.vue:110,116）：两条路线的字母编号不承载信息，直接用「普通检查 / AI 深度审查」即可。
9. 轻微：原生表单「拉取 /models」（settings_view.py:130）暴露 API 端点名，可改「获取模型列表」。

## 优化方案（按优先级，均不改动文件，仅给出改法）

**P0 —— 可达性硬伤**
1. **提亮 Web 亮色 `--ink-3`**：styles.css:52 `rgba(0,10,30,0.52)` → `0.60`（对比度 3.9→约 4.7:1，过 AA）；或全局把 ink-3 用途限制在 ≥12px 粗体（大字阈值 3:1 已达标）。一处变量改动，全站受益。

**P1 —— 一致性（低成本高感知）**
2. **统一「需要确认」**：SecurityView.vue:25 的「待确认」改为「需要确认」，与 StatusBadge/筛选器/行内按钮拉齐；App.vue:895,898 的「待确认项」同步。
3. **「完全删除」改名**：App.vue:584 `confirmLabel: '完全删除'` → `'删除'`，恐吓交给 message 里的后果说明（已写得很好）。
4. **统一跨层动作/实体名**：定一份术语表（建议 Web 为准：复制注入提示词、记忆库、技能库），原生侧 settings_view.py:41、skill_view.py:102、main_window.py 导航与 memory_view.py:70 页头照表替换；Web 侧无需动。
