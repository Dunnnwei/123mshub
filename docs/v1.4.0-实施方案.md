# 123 MSHub v1.4.0 原生壳实施方案

> 工作分支：`native/v2`  
> 对照文件：《v1.4.0-原生化总体方案.md》《v1.4.0-迭代历史与避坑清单.md》  
> 技术基线：[v1.4.0-技术架构.md](v1.4.0-技术架构.md)

## 目标和边界

本切片把 v1.3.3 的记忆业务核心接进 PySide6 原生桌面壳，先完成总体方案 §6 的 v1.4.0 MVP：主窗口、侧栏导航、记忆库、设置、亮暗主题和本地图谱 web 岛。既有 `src/mshub` 模块不改公共语义，原生代码只新增在 `src/mshub/native/`。

技能库和安全中心保留导航位，但显示 v1.5.0 的明确状态。拖放、文件关联、通知、托盘和系统主题跟随属于 v1.6.0，未在本切片伪造完成。

## 三个切片

### v1.4.0-a：原生壳与服务适配

- `mshub.native` 入口和 PySide6 `QMainWindow`；
- 236px 侧栏、记忆库列表/详情/编辑/新建/软删除；
- 投递箱预览、收编和丢弃；
- 复制现有注入提示词；
- `MemoryFacade` 只组合现有 `MemoryService`、`ConfigStore`、`Database` 和 prompt builder；
- `TaskRunner` 用 `QThreadPool` 承担列表、详情、保存、软删除、自愈和图谱数据预热；
- 设置页写回现有 `%APPDATA%\\mshub` 配置目录。

### v1.4.0-b：图谱 web 岛

- `web/native-graph/` 使用仓库既有 Sigma、Graphology 和 ForceAtlas2 版本；
- Vite 构建产物落到 `src/mshub/native/graph/`，构建插件补回 Qt 提供的 `qrc:///qtwebchannel/qwebchannel.js`；
- `GraphView` 首次导航时才创建 QWebEngineView、profile、page 和 channel；
- `GraphBridge` 保持 `getGraph/openMemory/getTheme/readGraphSettings/writeGraphSettings` 协议；
- 图谱优先使用 QThreadPool 预热的 `link` 缓存，缓存未到位时同步兜底；
- file/qrc 页面上的 FA2 worker 被 Chromium 拦截时执行有界同步 FA2，不启动 localhost；
- 拖拽在同步模式下执行短批次 reheat，页面销毁时停止 worker 和事件监听；
- 请求拦截器只允许本地协议，禁止远程页面、CDN、远程字体和图片。

### v1.4.0-c：打包与真实仓库冒烟

- PyInstaller onedir 入口为 `mshub.native.__main__`；
- 显式保留 `QtWebEngineProcess.exe`、QtWebEngine resources、WebEngine locale、平台插件和图谱静态资源；
- `scripts/native/prune-webengine.ps1` 只移除调试包、开发者工具、未用 locale 和 QML tooling，并对每个删除路径做发布目录边界检查；
- `--smoke-graph` 为隐藏 QA 入口，使用真实 Windows platform 加载 file 页面和 WebChannel 后由定时器退出；
- 发布目录附 `SHA256SUMS.txt`，运行期不创建 TCP 监听。

## 开发与验收命令

```powershell
$env:PYTHONPATH = "src"
& .\.venv\Scripts\python.exe -m pytest
& .\.venv\Scripts\python.exe -m compileall -q src/mshub/native
& .\web\node_modules\.bin\vite.cmd build --config .\web\native-graph\vite.config.mjs
& .\scripts\native\build-native.ps1
```

构建脚本会先跑测试，再生成 `release/native-v1.4.0/123mshub/`，检查图谱和 WebEngine 关键资源，裁剪运行时，使用 Windows 图形平台执行图谱冒烟并生成 SHA-256。

当前回归基线为原有 174 项服务层测试加 9 项原生测试，共 183 项；测试中的两个依赖弃用警告来自 FastAPI/Starlette 与 httpx 组合，不是本切片新增失败。

开发模式：

```powershell
$env:PYTHONPATH = "src"
& .\.venv\Scripts\python.exe -m mshub.native --repo D:\MSH
```

## 评估口径

- 配置目录以当前 `ConfigStore.SERVICE_NAME = "mshub"` 的真实行为为准，即 `%APPDATA%\\mshub`；总体方案中出现的 `123mshub` 目录名没有被悄悄另建，以免老配置失效。
- 主进程与 QtWebEngine renderer/GPU/profile 分开记录。当前构建主进程 Private Bytes 约 126.83 MB；Windows 工作集约 237.64 MB，后者列为待继续压缩/观察项，不用 Private Bytes 数字冒充工作集达标。
- 首次主窗句柄在本机实测约 1.08 秒；首次图谱页启动成本单独计算。
- 旧程序约 26 MB 的体积不可与原生 WebEngine onedir 直接比较；当前 345.81 MB 是包含 Chromium 的实际成本。

## 回滚

`master` 保留 v1.3.x 发布线；原生化只在 `native/v2`，不改旧入口和既有仓库格式。若后续图谱岛或 PyInstaller 资源出现阻断，仍可从 `master` 使用原 web 线，原生分支可独立修复或废弃。
