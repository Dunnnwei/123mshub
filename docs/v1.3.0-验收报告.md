## 体验目标对应

- 启动/更新涉及的 Git 和 bundle 子进程统一使用 Windows `CREATE_NO_WINDOW`，避免命令行黑窗；没有新增自启动、服务、管理员权限、未知下载执行或混淆代码。
- 导航已经按记忆库、记忆图示、技能库、安全中心、设置排列；侧栏与页头复制注入统一皇家蓝主按钮，添加技能使用描边按钮。
- 详情抽屉在接口返回前先呈现，加载状态和错误不阻塞关闭；宽度覆盖主工作区，小屏全宽。
- 迁移信息在 manifest / index.json / SQLite / 列表详情中保留；可识别 WorkBuddy、ZCode、Claude Desktop、Cursor 来源，无法识别时显示“外部仓库”，不编造平台。
- 技能库提供来源、资产类别、用户标签分层筛选，标签展开/收起，拉框多选和批量查版本、更新、A/B 安全检查、信任、降级；本地自研和项目会自动跳过不适用更新。
- “需要确认”本身就是可点击的信任入口；记忆库支持拉框/勾选后的批量分类、标签、AI 主题补全和软删除；记忆图示只绘制双链/共同标签，并在图例中说明依据。
- 设置增加 System/中文/English 选择、镜像候选按钮和只读代理检测。代理检测只填草稿，保存后才生效。

## 代码审查和误报风险审查

已对 `src`、`packaging`、`scripts` 做关键字与行为审查。外部进程仅有 Git bundle/clone/remote 操作，且捕获 stdout/stderr、带 UTF-8 解码、超时和 Windows 隐藏窗口参数；网络请求仅来自用户触发的 GitHub/镜像/API/AI 功能。未发现 `os.system`、`eval/exec`、计划任务、自启动注册、服务安装、UAC 提权或二进制混淆。`scripts/verify-release.ps1` 中的 `Start-Process` 仅用于发布验收启动 EXE。

PyInstaller 使用公开 `--windowed --onefile` 入口和明确的资源清单，没有隐蔽解包逻辑或持久化行为。Windows 杀毒产品仍可能对未签名单文件 EXE 产生启发式误报，这是签名信誉问题而非新增行为；用户可用发布目录的 SHA256SUMS 校验，或在企业环境用自有代码签名证书签发后分发。

## 已知限制

- 当前会话没有 Playwright MCP `browser_*` 工具，无法留存四个浏览器断点的 MCP 截图；已用独立 EXE 清洁环境、HTTP 冒烟、类型/构建和全量后端测试替代功能黑盒验收。发布前建议在有 Playwright 的机器补做 375/768/1024/1440 四断点截图。
- 界面语言设置已落库并在设置页可选；现有大量产品文案仍以中文为基线，English 完整词典需要后续内容批次逐屏补齐，不影响中文用户的本版功能。
- `release/v1.3.0` 和 `release/123mshub-v1.3.0-win64.zip` 被仓库忽略规则排除，但已在本机生成，可直接交付；源码发布需按项目原有发布策略取出这些产物。
