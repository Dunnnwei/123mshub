# 123 MSHub v1.4.0 起原生化总体方案（战略级提示词）

> 本文档是 v1.4.0 起原生化重构的**总纲**，供执行 agent 从头开工。文中「硬性约束」
> 与「验收标准」不可协商；标注「实现自由」的部分由你选择技术路线——你有足够空间，
> 但每处偏离推荐路线的决策必须先写决策记录（见 §7），获用户确认后再动手。

---

## 0. 背景与战略意图（为什么做这件事）

123 MSHub 是给「人」用的 Windows 桌面工具，为本地 agent（ZCode、WorkBuddy、Claude
Desktop、Cursor 等）管理共享记忆库与技能库。当前 v1.3.3 采用「FastAPI + localhost:8766 +
Vue/WebView2」架构，功能已完整、测试已稳定（174 pytest + 7 前端测试全绿）。

**从长远考虑，产品将转向原生桌面架构**，动机按权重排序：

1. **依赖链长期可控**：现在同时追 WebView2 Evergreen（微软自动升级、行为漂移、锁不了版）
   + vue/vite/sigma.js 三条 npm 生态 + 双构建链；原生收敛为一个工具包，版本自锁；
2. **部署独立**：干净 Windows 解压即用，WebView2/.NET 前置依赖与环境依赖包（400MB）从
   产品形态中消失；
3. **端口模型整类问题连根拔掉**：无 localhost 监听 = 无安全暴露面、无端口占用/双开逻辑、
   「本地工具零网络行为」的干净信任叙事；
4. **进程内直调**：UI↔业务逻辑从 HTTP+JSON 变函数调用/信号槽，大仓库场景长期受益；
5. **系统集成深度**：原生文件对话框、拖放导入、文件关联、托盘、系统通知、跟随系统主题；
6. **单语言栈工程复利**：一套类型检查、pytest 直测 UI、单进程调试。

**版本线策略**：v1.3.x（web 版）继续作为对外发布线，直到原生线功能完全对齐后才切换。
重构期间用户无感；重写失败的最大损失是一段分支，不是产品。

## 2. 已定决策（不要再议，直接执行）

以下经用户拍板，执行 agent 不得更改、不得用「更优方案」替换：

1. **原生化方向与四步里程碑**：v1.4.0 原生壳 MVP → v1.5.0 功能对齐 v1.3.3 → v1.6.0
   深度集成与性能 → v2.0.0 发布线切换（详见 §6）；
2. **业务核心零改动**：`src/mshub/` 只允许「新增适配层文件」，不允许修改既有模块的
   公共语义（函数签名、数据格式、行为契约）；
3. **数据格式完全兼容**：现有仓库（`memory\MEMORY.md` + `notes\*.md` + `inbox\`、
   技能库存储、`.meta\`、SQLite 缓存、`%APPDATA%\123mshub\` 配置）**零迁移**——
   v1.3.x 打开过的仓库，原生版必须直接可用；原生版动过的仓库，v1.3.x 也必须能开；
4. **图谱页走 web 岛**：sigma.js/WebGL 生态没有原生对等物，图谱以嵌入式本地页面形态
   长期保留（无端口、无服务，见 §4.3）；
5. **产品身份不变**：免费 · 全开源（MIT）· 无账号 · 无云端 · 无订阅 · 数据全在本地文件夹；
   中文界面；产品名与注入提示词协议（含连通暗号「天王盖地虎 / AI镇河妖」、仓库触发词、
   记忆/技能实数播报）内容保持与 v1.3.3 一致。

## 3. 产品需求（原生版必须做到的最终结果）

### 3.1 功能对齐清单（v1.5.0 验收的基准，缺一不可）

以 v1.3.3 实际行为为准（`RELEASE_NOTES.md` 各版本段落 + 程序实测）：

- **记忆库六场景**：审核 agent 投递（inbox 红点 → 预览 → 收编/丢弃）、手动记一条、
  搜索查阅（标题+描述+标签+正文全文）、修正编辑（frontmatter 表单 + 等宽正文 + `[[双链]]`
  展示）、软删除（`.meta\memory-trash\`）、总览分发（统计 + 复制注入提示词）；
- **记忆图示**：v1.3.3 图谱全部行为（悬停一度聚焦、邻边类型色高亮、非邻居淡出、
  拖拽重热 FA2、搜索变暗不隐藏、亮暗主题混色、设置持久化、3000 节点流畅）；
- **技能库**（继承 123skillrepo 全部）：GitHub/本地入库、标准/全仓安装、程序仓克隆、
  安全检查 A/B 路线、标签与来源徽章、中文备注 AI 翻译、编辑信息、更新与备份、软删除、
  跨机重新识别、镜像/代理、点文件容器、git.bundle 自愈、批量操作；
- **导入记忆技能库**：四类来源识别（123mshub 互导 / DSH brain / Engramory 式 /
  散装 + SKILL.md 目录）、扫描预览 → 后台导入（进度、去重、日报）、幂等、
  导入即安全扫描、symlink 防护、NFKC 归一化、BOM 容忍；
- **整理与日报**：手动归纳（本地盘点 + AI 分析）、值守 Agent 提示词导出、日报查看；
- **注入提示词中心**：生成/复制注入提示词与值守提示词（含暗号实数）、提示词注入
  规则红条警告；
- **设置**：仓库位置、AI 接口、GitHub Token、语言（中/EN/系统）、镜像与代理检测、
  记忆库位置覆盖（高级折叠区）、导入入口；
- **跨机**：文件夹自行同步，启动自动对账（冲突副本隔离、索引重建、懒对账）。

### 3.2 原生版新增能力（原生化红利，v1.6.0 交付）

- 干净 Windows 解压即用（无 WebView2/.NET/Git 前置检查，环境包退役）；
- 拖放导入：文件夹/文件拖进窗口直接触发导入扫描；
- 文件关联：`.mshubrepo`（或等价标记文件）双击用本程序打开仓库（实现方式自由）；
- 系统通知（导入完成、日报生成）、托盘（可选，默认关闭）；
- 跟随系统暗色/亮色主题即时切换；
- 高 DPI 与多屏混合缩放正确渲染。

### 3.3 非功能硬指标

| 指标 | 目标 |
|---|---|
| 冷启动（中端硬件，255 技能仓库） | ≤ 3 秒进主窗可交互 |
| 常驻内存（典型使用） | ≤ 200MB（含图谱页打开） |
| 图谱 | 3000 节点 / 6000 边布局收敛 <5s、交互 60fps（沿用 v1.3.3 冒烟测试口径） |
| 导入 | 60 记忆 + 255 技能幂等导入零损失（沿用 v1.2.4 验收口径） |
| 权限 | 不请求管理员、不装服务、不自启动、不混淆、不访问未知网络地址 |
| 安全 | 全程无 TCP 监听（这本身就是验收项：`netstat` 无新增监听端口） |

## 4. 技术结构（方向指引 + 实现自由）

### 4.1 推荐路线（默认选项，可直接采用）

- **UI 框架：PySide6（Qt6）**——唯一能零成本 import 现有 Python 业务核心的成熟原生栈；
- **UI↔核心通信**：Qt 信号槽 + QThread 工作线程（耗时任务不阻塞 UI 线程）；
- **视觉**：QSS 移植 `design-system/MASTER.md` 的 token；玻璃拟态用
  半透明 + QGraphicsEffect（模糊/发光）近似，做不到 1:1 时保色彩与层级、降模糊强度；
- **图谱岛**：QWebEngineView 加载本地静态页 + QWebChannel 双向通信（§4.3）；
- **打包**：PyInstaller **onedir 目录模式**（冷启动快、杀毒摩擦小）+ 代码签名预留。

### 4.2 实现自由区（你选路线，但要对结果负责）

- 窗口/组件分解、导航结构、状态管理模式；
- 线程模型细节（QThread / 线程池 / 事件循环集成方式）——只要 UI 线程不卡、
  任务可取消、异常有兜底；
- QSS 组织方式与主题切换机制；
- 图谱岛与原生层的数据桥细节；
- 打包脚本与发布流程的具体实现。

**偏离推荐路线的协议**：如认为有更优栈（如另一 Python 原生工具包），必须先产出
`docs/v1.4.0-技术选型决策记录.md`，逐条对照 §2 硬约束论证（尤其：能否零改动 import
`src/mshub`、能否承载 WebGL 图谱岛、测试可行性），**经用户确认后**方可替换。
默认禁止引入需要重写业务核心的栈（.NET/WPF、Flutter、Tauri 等在此轮明确排除——
Tauri 仍是 WebView，不解决本次重构的核心目标）。

### 4.3 图谱 web 岛（长期保留的唯一 web 组件）

- 以本地静态页面承载现 `web/src/components/MemoryGraph.vue` 的等价实现
  （sigma.js + graphology + FA2 worker 依赖照搬，行为对齐 v1.3.3）；
- **无 HTTP 服务、无端口**：页面经 QWebEngineView 本地加载，数据经 QWebChannel
  （或等价注入桥）从业务核心直供 `/api/memory/graph` 等价数据（含 `kinds` 参数语义）；
- 视觉基准仍是 `docs/design/obsidian-graph-*.png`；
- 设置持久化：图谱页内设置须落持久存储（QWebEngineView profile 持久化或经原生层
  写配置——v1.3.3 在 pywebview 上踩过 private_mode 丢设置的坑，勿重蹈）；
- QWebEngineView 自带 Chromium（+80MB 体积）是已接受的权衡：它随程序分发、
  不依赖系统 WebView2，部署独立性不受影响。

## 5. 硬性约束（红线，逐条可查）

1. `src/mshub/` 既有模块零语义改动；新增文件限于适配层（命名建议 `src/mshub/native/`）；
2. 数据格式与 `%APPDATA%\123mshub\` 配置目录双向兼容（§2.3）；
3. 全程无 TCP 监听（图谱岛、内置预览、任何页面均不得起本地服务器）；
4. 每个里程碑：`tests/` 174 项原样全绿 + 新增 UI 测试全绿 + 冒烟验收通过，才算完成；
5. 工作分支：`native/v2`（新建），master 保持 v1.3.x 发布线；里程碑达成才合回；
6. 文档同步：每个版本产出 `docs/vX.Y.Z-实施方案.md` + `docs/vX.Y.Z-验收报告.md`，
   `RELEASE_NOTES.md` 随版本追加；
7. 禁止伪造验收：清单每项必须真实执行并在报告中给出证据（命令输出/截图/数据）；
8. 资源与安全姿态：§3.3 权限与安全两行适用于所有里程碑的所有构建。

## 7. 工作纪律（给你自己的规矩）

1. **先读后写**：动手前通读 `src/mshub/` 业务核心与 `RELEASE_NOTES.md` 全部版本段，
   理解行为契约再写适配层；
2. **决策记录先行**：任何偏离 §4.1 推荐路线的选择，先写决策记录获用户确认（§4.2）；
3. **小步提交**：每完成一个可运行切片就 commit（分支 `native/v2`），不积攒大爆炸；
4. **不拆东墙**：master 上的 v1.3.x 修复需求与重构冲突时，先在 v1.3.x 线修，再 cherry-pick；
5. **诚实汇报**：做不到、没做完、有疑虑的项，明确说出来，不粉饰。
