## 设计针对性结论

### 结论：有明确产品语义锚点，但视觉结构仍有中等模板化残留

整体设计针对性为 **3.2/5（中等偏上）**。它已经不是一个完全可替换的通用后台模板：

- 记忆页的“用户 / 项目 / 参考 / 反馈”分类直接来自共享记忆模型。
- 每行同时表达标题、描述、类型、来源、标签和日期，符合知识资产的判断任务。
- 技能页把来源、中文备注、安全状态、标签和更新时间放到同一张表里。
- 安全页明确区分“路线 A · 离线”和“路线 B · AI”，符合高成本/联网操作必须显式选路的产品约束。
- 图谱的节点类型颜色、双链、共同标签边、节点浏览器和 ForceAtlas 参数都与“共享记忆关系”有关，而非一般销售 Dashboard。
- 异步编辑、投递箱、索引源文件、日报和后台任务这些行为也有产品语义。

仍然可以把以下部分原样换进仓库管理器、资产 Dashboard 或内部 CRUD 工具：

- 236px 侧栏 + 五个图标导航 + 底部后台任务，是常见的桌面管理壳层。
- 统计数字按钮、搜索框、筛选下拉、右侧一组描边按钮是通用管理页排列。
- SHARED MEMORY、SKILL LIBRARY、SAFETY CENTER、LOCAL CONFIGURATION 这组英文全大写眉题没有帮助用户理解当前任务，反而加强了模板感。
- 所有页面都使用“标题 + 描述 + 一排动作”的相同骨架，但没有用“当前仓库 / 当前记忆 / 风险等级 / 可复用性”这些产品上下文形成真正的视觉分层。
- 图谱使用 OBSIDIAN GRAPH VIEW，虽然表达了双链关系，却借用了另一个产品类别的命名语气；应改成 123 MSHub 自己的“共享记忆关系图”语言。

**模板化残留主观估计：约 38%。** 这个百分比是对可替换的布局模式、眉题、按钮阵列和通用控件比例的设计判断，不是自动检测结果，也不是代码覆盖率。

## 视觉检查

### 记忆页

浅色和深色截图都能快速确认“这里是共享记忆”，因为页面标题、统计和列表元信息都稳定。主蓝色按钮“复制注入提示词”有明确视觉权重，侧栏 active state 也很容易找到。

目前的主要问题：

1. 页头、统计 chip、搜索/筛选行、列表和底部整理动作同时争夺第一视线。真正的主任务是“搜索 → 选择 → 查看/编辑”，但视觉上“复制提示词”“新建”“编辑”“投递箱”“归纳整理”几乎是同一层级。
2. 截图中只有一个条目时，列表容器下方留下大块白色/深色空白，页面显得像未完成的模板。应让列表根据内容收缩并把详情、推荐下一步或最近活动放在真实可用的位置。
3. 截图中的品牌字样在侧栏宽度下接近或出现右侧裁切（深色截图表现为 123 MSHu），应保证 logo/品牌名称始终完整，或明确采用“123”紧凑品牌态而不是半截文字。
4. active 导航的蓝色填充很好，但外围完整蓝色焦点框在截图中显得像整块列表被选中，焦点语义和选中语义需要分离。
5. 行内元信息使用 11px 小字，类型、来源、标签、日期虽完整，但在长标题和深色模式下容易成为二次扫描成本。

### 图谱页

图谱源码的产品关系是成立的：双链、节点类型、共同标签边、孤儿节点、缩放、Force 参数和可键盘打开节点都服务于记忆关系探索。加载、Canvas、WebChannel 和 reduce-motion 也有明确状态处理。

设计风险在于它与 Native 页面过于分离：

- OBSIDIAN GRAPH VIEW 是借来的产品语气，弱化“123 MSHub 共享记忆图”的品牌归属。
- 图谱使用单独的 HTML 标题、toolbar、settings panel 和 legend；其间距、圆角、按钮和浮层虽共享 token，却没有共享 Native 页面里的任务上下文。
- Filters / Display / Forces 的英文分组把设置推向技术用户，第一次打开图谱的人不容易知道哪些开关会影响查找任务，哪些只是演示参数。
- 节点浏览器是很好的键盘等价入口，但它隐藏在图谱状态中，初次使用者不会知道可以通过它绕开 canvas。
- 图谱动态微动有性格，但应把“有意义的关系探索”放在情绪峰值，而不是让动效成为唯一的记忆点。

### 技能与安全页

技能表是信息密度最高、最容易帮助熟练用户的页面：名称、来源、备注、安全、标签和更新时间共存，52px 行高也比早期压缩表格可靠。

问题集中在动作和风险层级：

- 详情动作包含离线检查、AI 检查、信任放行、更新、软删除、编辑信息六个按钮，当前视觉上没有推荐路径或风险分层。
- 本地技能禁用更新是正确的业务语义，但“为什么不能更新”主要依赖 tooltip/状态，不够就地。
- 安全页把路线选择、批量检查、刷新和结果表放在同一条工具栏，用户难以判断下一步是先选路线、先筛待确认、还是直接打开报告。
- unchecked 等状态词若没有中文解释，第一次用户会把“未检查”误读成“通过”。

### 设置页

设置页的三 tab、滚动表单和滚动区外固定保存按钮是良好的基础，尤其适合 960×640 的紧凑窗口。问题是表单的信息架构仍然像“把所有配置放进一个后台面板”：

- 仓库、抓取方式、语言、主题、代理、镜像在同一 tab，用户需要自己判断哪些是启动关键、哪些是高级网络配置。
- AI 接口地址、模型、密钥、连通性、清除密钥和 GitHub Token 聚在一起，但缺少“密钥只保存本机 / 当前草稿尚未生效”的强提示。
- 保存反馈只在底部 status 区出现，保存前后没有可见的“草稿 / 已保存”状态。
- 紧凑设置截图底部显示 123 MSHub Native 1.6.1。源码版本已经是 1.7.0，因此这张证据图要么是旧样本、要么说明生成截图时版本标签未同步；在 v1.7.1 交付中必须重新截取并核对版本，不能让视觉证据与发布版本冲突。

## 认知负荷检查（Impeccable 8 项）

结论：**6/8 项失败，属于高认知负荷，需要优先调整。** 失败主要来自信息和动作同层级堆叠，而不是业务本身过于复杂。

| 检查项 | 结果 | 证据与判断 |
|---|---|---|
| Single focus：单一焦点 | **失败** | 记忆页同时展示 7 个统计、3 个页头动作、搜索/类型/排序/投递箱和底部 4 个整理动作；主路径不够突出。 |
| Chunking：分块不超过 4 项 | **失败** | 7 个统计 chip、5 个导航项、技能 7 列、安全工具栏和图谱多组设置都超过 4 项，没有持续的分组标题或折叠层级。 |
| Grouping：相关内容成组 | **通过** | 侧栏、页头、搜索筛选、列表、详情、图谱 settings、设置 tabs 都有边界和 proximity；信息本身能找到，只是组内层级还不足。 |
| Visual hierarchy：视觉层级 | **失败** | 蓝色主按钮存在，但 chip、描边按钮、页头动作、底部动作和表格操作之间差异小；大面积空白又使次要元素显得被放大。 |
| One thing at a time：一次只处理一个决定 | **失败** | 记忆编辑窗口同时容纳身份、标题、描述、类型、标签、正文、双链、预览、软删除和保存；技能详情同时放置六个动作。 |
| Minimal choices：每个决策点不超过 4 个 | **失败** | 页头、技能详情、图谱设置和设置 tab 都有 5+ 个同时可见选项；批量操作出现后还会增加更多动作。 |
| Working memory：不依赖跨页记忆 | **失败** | 用户需要记住路线 A/B、unchecked 含义、来源/更新限制、抓取方式和当前仓库上下文；报告、状态和配置分别分散在表格、弹窗和 status bar。 |
| Progressive disclosure：按需揭示复杂度 | **通过（但不完整）** | 批量栏、记忆详情、技能详情、图谱设置、编辑器都使用隐藏或独立窗口；但打开后一次性展示大量字段和动作，设置三 tab 仍然以“全量配置”开场。 |

## 情绪路径与峰终体验

1. **进入：平静且有方向。** 侧栏 active blue、品牌名、页面标题和低饱和背景让用户知道自己进入了一个本地工作台，而不是营销页面。这是当前最成功的情绪起点。
2. **探索：效率感成立。** 搜索、统计、筛选、批量栏和表格适合熟练用户；行内元信息让知识资产看起来可追溯。图谱的节点关系和轻微微动可以提供探索的情绪峰值。
3. **高风险决策：信任感下降。** “信任放行”“AI 检查”“更新”“软删除”同在一排时，系统没有告诉用户哪个是建议路径、会产生什么外部影响、是否可恢复。安全流程需要先给风险摘要，再给动作。
4. **等待与失败：基础有，但不够安抚。** 编辑器先显示加载、后台任务和状态栏是正确方向；但失败状态仍偏技术化，缺少“原因 → 处理 → 重试”的闭环。
5. **完成：峰终偏弱。** “设置已保存”“已刷新”通常只出现在底部 status bar，短暂且低权重；复制提示词、批量修改、导入和安全扫描完成后没有形成稳定的可回顾结果。建议在页面内保留最近一次操作摘要，尤其是安全和批量任务。
6. **结束：缺少信心确认。** 关闭编辑器后用户无法快速看到“哪些字段已写入、哪些后台任务仍在运行、软删除如何恢复”。当前视觉上更像操作完成就离开，而不是留下可验证的收尾。

## 做得好的 3 件事

### 1. 内容模型已经进入视觉系统

类型、来源、标签、日期、技能安全状态和路线 A/B 不是假数据装饰，而是直接服务判断。记忆行双行结构也符合标题优先、辅助信息次之的阅读顺序。

### 2. 基础设计系统扎实

design_tokens.json、Qt QSS、图谱 CSS、浅色/深色 token、焦点边界、统一行高、Dream Han Sans CN 与 Cascadia Mono 的分工已经形成可维护基线。浅色/深色截图的蓝色行动色、纸张感背景和细边界具有稳定识别度。

### 3. 操作效率和可访问性方向正确

Ctrl+1…5、Ctrl+F、Ctrl+S、批量动作、异步详情、脏数据拦截、图谱节点下拉和原生表单 label 绑定为不同用户提供了实际效率。很多团队会先做漂亮卡片而忘记这些，这一版的操作基础反而是可靠的。

## 优先问题

### [P1] 页面所有动作的视觉权重过于接近

**现象：** 记忆页的“复制注入提示词 / 新建记忆 / 编辑选中”、统计 chip、筛选、投递箱和底部整理动作形成多个相邻按钮带；技能详情的六个操作也没有分主次。

**影响：** 用户很难在 5 秒内判断“现在最应该做什么”。高频路径被低频维护动作淹没，视觉节奏变成一排控件，而不是一条任务路径。

**修复：**

- 每个页面只保留一个 primary action；记忆页默认突出“新建记忆”或“打开选中”，复制提示词放进辅助菜单。
- 将日报、值守提示词、索引源文件、批量 AI 等低频动作收入“更多”分组。
- 安全页将“推荐路线”和“结果报告”做成明显的主路径。
- 统计 chip 从按钮改成可筛选的 compact summary，只有当前激活项才使用强调边界。

**建议命令：** /impeccable bolder + /impeccable layout + /impeccable distill

### [P1] 字体对比和页面节奏仍偏保守，产品重点没有被放大

**现象：** 页面标题足够清楚，但正文说明、行内元信息、状态栏和设置 label 都偏轻；英文字段眉题重复出现；列表只有一个条目时，下方留下巨大空白。页面在“安静”与“无重点”之间摇摆。

**影响：** 用户要扫视大量小字才能确认来源、状态和日期；真正的高价值判断没有形成节奏。截图中的大面积空白也让产品显得像模板尚未填满。

**修复：**

- 使用更强的字体对比：页面标题与主数值加大字重/字号，辅助字段收紧到一行，风险/状态使用更强的色彩和字重。
- 统一中文 section label，删除不能增加理解的英文眉题，或将其缩小为极少数品牌标记。
- 让列表/详情根据真实内容伸缩；无内容时给出下一步引导、最近活动或示例结构，而不是保留整片空表面。
- 校正侧栏品牌在 176/236 两个宽度下的完整性。

**建议命令：** /impeccable bolder + /impeccable typeset + /impeccable layout

### [P1] 安全中心没有把风险和路线选择变成可读的决策阶梯

## 其他细节

- 记忆页当前的 copy_prompt 主按钮适合 Agent 工作流，但它不一定是新用户进入页面后的第一任务；应根据是否已有条目和是否有待收编内容动态调整主动作。
- “总数 / 用户 / 项目 / 参考 / 反馈 / 本周新增 / 待收编”七个统计最好变成“总数、待处理、最近变化”三组摘要，类型统计放进可展开筛选。
- QTableWidget 表格的安全状态、标签和更新时间使用单元格文字承载，适合数据密集场景；但可排序列、当前筛选摘要、隐藏列提示应变成可见上下文。
- 图谱底部 legend、右下角缩放按钮和左上角节点浏览器属于正确的辅助层；应保持其不遮挡关系，不再叠加更多装饰性浮层。
- 深色模式基础对比度很好，但深色截图中页面大面积单色表面会使层级依赖边框；可用少量 raised surface 或状态色区分“列表 / 详情 / 高风险报告”。
- 设置页的“关于 123 MSHub”单独放在右上角，位置稳定但不符合主要配置任务；可放入帮助菜单或页尾版本信息附近。
- 主导航只有五项，数量本身在工作记忆范围内；问题不在数量，而在后台任务、关于和维护入口没有形成同一信息架构。
