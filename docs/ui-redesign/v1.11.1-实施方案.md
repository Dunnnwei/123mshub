# 123mshub v1.11.1 实施方案

日期：2026-10-03。基线：当前干净工作区 v1.11.0；目标：v1.11.1 本地完整包交付。

## 需求与根因

1. 添加技能窗口只有来源字段，服务层一律把来源交给 GitHub 地址解析，目录路径必然触发“作者/仓库”校验。增加独立“命名”字段，并实现本地目录、ZIP 的真实读取与安装流程；命名用于条目身份和新安装目录，来源仅用于读取文件及溯源。
2. 技能编辑只有翻译功能，无法从缺少说明的技能文件生成介绍。增加“AI说明”，复用设置中的 AI 网关、密钥、模型，查询已安装条目的 SKILL.md / README 等说明文件，生成中文和英文推荐说明。
3. 技能仓库批量操作行删除“已勾选条目：”。
4. 记忆页已有连选回调，但状态标签位于隐藏的编辑窗口。新增列表页底部状态标签，连选范围按其他列表的“已连选第 X–Y 行（共 N 项）”格式显示在左侧，操作提示仍在右侧。

## 实现约定

- 保留 v1.11.0 的 123ui5.0 视觉令牌、页面结构、业务接口和本地图谱架构。
- 来源支持 GitHub URL、owner/repo、本地目录及 .zip。浏览按钮提供目录和 ZIP 两种选择；来源变化时建议名称，用户手动命名后保留输入。
- 命名允许中文、英文、数字和普通名称符号，兼容作者/仓库身份；拒绝路径穿越、Windows 非法字符、保留设备名与空名称。校验错误留在添加窗口，允许就地修改。
- 本地来源走临时快照再复用原有解析、离线检查、清单、索引和事务安装。ZIP 支持根目录文件和单层包裹目录，限制文件数量/解压体积并拒绝越界、链接、重复路径。保留原始目录及 ZIP。
- 本地条目持久化为 local 来源；自定义远程名称在更新时保留。预览与安装使用同一命名规则，重名不静默覆盖。
- AI 仅使用当前技能已安装的说明材料和现有元数据；不把模型推测当作联网搜索结果。后台调用，成功时同时覆盖左右说明编辑框，失败保留原说明。通过“保存”写入仓库。
- AI 请求绑定编辑会话与条目复合身份；切换条目、关闭窗口、开始新请求或请求期间手工修改后，旧响应不覆盖新内容。生成和翻译互斥，防止异步写错条目。

## 验证与交付

- 回归验证：目录路径含中文/空格、自定义名称、ZIP 根目录/包裹目录、非法压缩路径、重名、文件/清单/数据库一致性、GitHub 命名及更新兼容。
- AI 验证：模拟网关成功/失败/不完整 JSON、材料边界、缺少配置、两栏覆盖、异步过期和手工编辑保护。真实第三方调用与模拟验证分开记录。
- 原生窗口验证：添加窗口、技能编辑窗口和记忆连选提示在亮/暗主题及常见缩放下的实际 Qt 渲染。
- 冻结版本：Python 包、pyproject、Web package/lock、uv.lock 项目版本及品牌测试同步到 1.11.1。
- 完整 pytest 通过后按 scripts/native/build-native.ps1 生成 release/native-v1.11.1/123mshub 与 release/123mshub-native-v1.11.1-win64.zip，包含 README-完整包.txt、SHA256SUMS.txt，并另存发布说明/发布正文。
- 核对最终 EXE 冻结模块及资源与源码一致、ZIP CRC 与 EXE 一致；使用真实 D:\\MSH、隔离配置运行最终 Windows EXE 图谱 smoke。验收报告明确区分离屏 UI、Windows 启动烟测和人工/真实供应商验收。
