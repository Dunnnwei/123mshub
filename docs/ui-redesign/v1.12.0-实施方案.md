日期：2026-10-20（Asia/Shanghai）。
基线：v1.11.4，提交 `39a872e`。版本：**v1.12.0**。

## 目标与范围

1. 保留记忆仓库、记忆图示、技能仓库、安全中心、设置、导入、AI、自动同步、后台任务与在线升级的现有功能、配置和数据格式。
2. 以 `D:/DiskWork/PJ/HAUI` 的本地 HAUI 0.1.0 为设计事实源，替换桌面所有应用自绘界面和图谱界面的旧 123UI/Stitch 视觉层。
3. 检查代码，优先修复可复现的状态、并发、主题、可访问性和发布问题，避免无证据的大范围业务重写。
4. 沿用 `release/native-vX/123mshub` + 单一完整 ZIP + README + SHA256 + 发布说明的交付惯例，完成 GitHub 源码与 Release 发布。

## 架构决定

现有应用是 PySide6 Widgets + 本地 QWebEngine/QWebChannel 图谱；HAUI 是 React 19 组件库。此次以 **HAUI 原生适配层**接入：从 HAUI 实际主题解析器导出完整主题、可读文字与控件派生令牌；复用其 Tabler 图标、字体与许可证；在 Qt 控件及图谱 CSS 上实现同一视觉规范。不会声称 Qt 正在运行 React/Radix 组件。保留原生操作系统文件选择器。

这样可完整替换视觉层，同时复用已经存在的 Qt 交互和 Python 服务，避免为换肤重写存储、网络、权限或任务业务。运行包无需访问 HAUI 原目录、Node.js 或开发服务。Qt 图谱继续只使用本地文件和 QWebChannel，不新增 TCP 监听。

HAUI 的 palette、mode、accent 独立；默认采用 HAUI Nous，保留旧用户亮/暗/系统外观设置。导出的原始 26 字段与适配规则入库，记录来源文件 SHA256，可重复生成。系统正文字体、Space Grotesk 标题、JetBrains Mono 代码，Tabler 图标，扁平内容区、细分隔线、统一控件和轻量浮层。移除旧靛紫渐变、重复外框、旧图标语言。

## 实施顺序

1. **基线与留档**：记录现有未提交内容，隔离本次提交；运行基线测试；检查发布脚本、版本面、升级链与凭证使用。
2. **HAUI 同步与适配**：创建可复跑资源导出器、主题解析数据、字体/图标/许可资源和 Qt 适配；更新图谱主题桥接。
3. **全界面替换**：导航与侧栏、页头、工具栏、列表、编辑/确认/导入/关于弹窗、设置页、后台任务、空/加载/错误状态全部使用共享 HAUI 规范；加入 palette 与强调色设置。
4. **代码优化**：基于实际审查结果修复并补充回归；检查异步旧结果、稳定身份、主题判定和退出清理。
5. **验证**：全量 Python 测试、前端相关检查、主题/焦点/缩放/弹窗/图谱实际渲染、打包 EXE smoke、包完整性、依赖与凭证检查、Defender 扫描。
6. **发布**：同步版本、发布说明、验收与限制，构建全量包，复核 ZIP CRC/文件集/哈希；提交本次文件，创建新标注标签，推送分支与标签，上传 GitHub Release 资产并回读校验。

## 安全与风险边界

采用标准 PyInstaller onedir、`upx=False`、无壳/无混淆/无自动提权，不关闭杀毒软件，不添加排除项。检查依赖、升级校验与归档路径、打包数据和凭证泄漏；对最终发布文件运行当前机器可用的 Defender。记录 Authenticode 状态。未持有代码签名证书时如实标记未签名；本机扫描不等于全部杀毒产品或 SmartScreen 的保证。

GitHub token 仅从用户指定文件在进程内读取，不输出、不写入源码、日志、Git remote 或发布资产。用户已授权版本选择和上传 GitHub，无需重复确认。
