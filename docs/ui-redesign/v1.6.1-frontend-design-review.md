## 这次设计要解决什么

123mshub 不是普通的文件浏览器，也不是把 AI 接口集中在一起的控制台。它管理的是本地 Agent 的共享大脑：一边是可复用的记忆条目，一边是可安装、可审查的技能与程序；用户还要能看到它们之间的关系、控制安全检查路线，并把仓库、镜像、AI 凭据和导入来源配置清楚。

现有 v1.6.1 功能已经完整，但界面把不同风险、不同工作频率的内容放在相同的视觉层级里：记忆条目、技能来源、检查状态、批量任务和设置表单都使用近似的容器和密度。因此用户需要先辨认界面，再判断下一步应该做什么。

新的视觉方向叫 **Shared Brain / Signal Desk（共享大脑信号台）**：

- 记忆仓库像一份可检索的工作档案，重点是标题、上下文、类型和最近变化。
- 记忆图示像一张安静的关系地图，重点是连接、聚焦、筛选和打开条目。
- 技能仓库像一份资产目录，重点是来源、用途、版本、标签和可执行动作。
- 安全中心像一张值守清单，重点是路线 A / 路线 B、风险等级和检查记录。
- 设置页像一份本地设备配置，不让路径、凭据、代理和导入操作混在一个“万能表单”里。

界面保留 123mshub 的皇家蓝、亮暗主题和玻璃质感动效语言，但把蓝色从“所有文字都抢注意力”调整为明确的行动、选中和焦点信号。紫、青、橙只承担记忆类型或安全语义，不作为装饰色随机出现。

## 目标用户

### 1. 本地 Agent 重度使用者

他们同时使用 ZCode、WorkBuddy、Claude Desktop、Cursor 或自定义 Agent，需要让多个 Agent 读取同一套记忆与技能。核心诉求是快速搜索、复制注入提示词、打开条目、查看来源和复用已有能力，不希望每次都理解底层目录结构。

### 2. 记忆维护者 / 内容策展人

他们会处理 Agent 投递箱、归纳日报、条目分类、标签和双链。核心诉求是判断一条内容是否值得收编、是否应该更新旧条目，以及修改后能否回看来源。

### 3. 技能库维护者

他们管理 GitHub 技能、本地自研技能和程序项目，关注来源、版本、中文备注、安装方式、更新能力和批量操作。核心诉求是列表可扫读、长名称不丢失、双击能查看详情、批量动作不会误伤本地自研内容。

### 4. 安全审核者

他们不一定是开发者，但必须知道某个技能是否检查过、检查走了哪条路线、有没有命中项、谁做过人工放行。核心诉求是风险状态显眼、路线选择明确、报告可追溯，不把“未检查”伪装成“安全”。

### 5. 首次配置者

他们第一次启动时只关心仓库在哪里、是否需要镜像、语言和主题如何设置、AI 与 GitHub 凭据是否有效，以及怎样导入已有资产。核心诉求是按任务分组、字段说明在旁边、保存结果清楚。

## 页面目标与核心任务

| 现有页面 / 预览页 | 页面目标 | 用户完成的主要任务 | 内容特点 |
| --- | --- | --- | --- |
| 记忆仓库 | 找到、判断并维护一条共享记忆 | 搜索、按类型/时间筛选、打开编辑、复制注入提示词、处理投递箱、归纳整理、查看日报 | 标题可能很长；描述是上下文；类型和标签需要同时可见；条目正文支持 `[[双链]]` |
| 记忆图示 | 发现记忆之间的关系 | 搜索节点、按类型筛选、切换共同标签边、复位/缩放、拖拽、点击打开条目 | 图形是主内容；节点大小代表连接数；颜色代表记忆类型；悬停时需要聚焦邻居 |
| 技能仓库 | 管理可复用技能与程序资产 | 搜索、按来源/资产类型筛选、添加、查看详情、离线检查、AI 检查、信任、更新、软删除、复制指定提示词、批量操作 | 名称常用 kebab-case 或 `owner/repo`；中英文说明并存；本地自研没有在线更新源 |
| 安全中心 | 让“未确认”和“已检查”一眼可区分 | 选择路线 A / 路线 B、批量检查待确认、查看摘要与报告、人工信任、刷新 | 安全状态不是普通标签；“0 项命中”与“尚未检查”语义不同；报告可包含多级严重度 |
| 设置选项 | 把本地运行条件配置正确 | 配置仓库、记忆覆盖目录、抓取方式、语言、主题、代理、镜像、AI 接口/模型/密钥、GitHub Token、重新识别、导入、打开仓库、关于 | Windows 路径、密钥掩码、异步检测、导入预览和保存反馈都需要稳定的表单层级 |
| 设计规范（仅预览） | 让设计选择可审阅、可对照 | 查看颜色、按钮、徽章、表单、字体和任务卡 | 仅用于本次评审，不新增产品路由 |

## 内容与表达判断

1. **动词优先。** “复制注入提示词”“新建记忆”“扫描预览”“批量离线检查”“保存设置”都直接说明结果，避免只写“确认”“执行”“处理”。
2. **状态必须带语义。** `safe`、`待确认`、`未检查`、`0 项命中`、`路线 A · 离线` 和 `路线 B · AI` 在视觉上分组，但不依赖颜色单独表达。
3. **路径和标识使用等宽字。** 仓库路径、`owner/repo`、kebab-case 名称、时间和版本号需要在长列表中保持可定位。
4. **中文说明允许一行截断，但不能让用户失去判断依据。** 列表展示简短说明，详情窗口保留完整内容；源、版本、安全和更新时间不被描述列挤掉。
5. **批量操作只在选择后出现。** 没有勾选时不占据主视线；勾选后显示已选数量，并让高风险操作与普通操作产生明显差异。
6. **异步工作要有可见去向。** 导入、重建、检查、更新和归纳会进入后台任务区；任务区显示任务、状态、进度和阶段，不能只在底部状态栏闪过一句话。
7. **设置是三类问题，不是一个长表单。** “仓库与语言”“AI 与凭据”“维护与导入”保留现有功能分组，视觉上提高组标题和说明的对比度。

## 视觉设计系统

### 设计关键词

安静的操作台、可检索的档案、关系信号、可信的状态、局部玻璃、蓝色焦点。

### 色彩

| 角色 | 深色值 | 亮色值 | 用法 |
| --- | --- | --- | --- |
| 应用背景 | `#0B0E14` | `#F2F4F8` | 页面底色，避免大面积纯黑 |
| 侧栏 / 标题栏 | `#0F1219` | `#F7F8FA` | 稳定导航和窗口边界 |
| 内容表面 | `#141926` | `#FFFFFF` | 列表、表格、表单承载层 |
| 输入表面 | `#1B2232` | `#F3F5F8` | 搜索和编辑控件 |
| 皇家蓝行动色 | `#0156FC` | `#0156FC` | 主按钮、选中条、焦点、进度 |
| 蓝色辅助文字 | `#8DB5FF` | `#0148D2` | 页面标题说明和链接语义 |
| 成功 | `#3DD598` | `#12864A` | 已检查、已保存、任务完成 |
| 待确认 | `#F5B84C` | `#B45309` | 未检查、需要人工判断 |
| 风险 | `#F2766E` | `#D23737` | 命中项、软删除、危险动作 |
| 类型青色 | `#2CC9C0` | `#0C8585` | 参考类记忆、关系边 |

玻璃只用于浮层、任务面板、图例和设置面板边界：半透明表面、细边框、轻微背景模糊和内侧高光。列表正文仍使用高对比的实体表面，保证长时间阅读和 Windows 缩放下的可读性。

### 字体

- 主字体：`Dream Han Sans CN`，回退到 `Segoe UI Variable Text`、`Microsoft YaHei UI`。
- 标题使用同一字体的较重字重，不用随机插入衬线或斜体制造“设计感”。
- 路径、技能标识、版本和时间使用 `Cascadia Code` / `Consolas`，让可复制的系统信息有明确边界。
- 页面标题、正文、辅助说明保持紧凑的 4 级字号层次；不把小字全部做成全大写标签。

### 版式

- 46px 原生窗口标题区；左侧导航固定 236px，主区内容宽度约 1180px。
- 页面标题负责回答“现在在哪里”，副说明负责回答“这里能做什么”，动作按钮紧跟在右侧。
- 记忆页采用统计带 + 搜索行 + 双列列表 / 编辑窗；技能与安全采用可扫读表格；图示页将关系图作为主表面。
- 列表行使用稳定的 44px 左右高度，标题和说明可以截断，但来源、状态、标签和时间保留。
- 圆角只表达层级：窗口/大面板 14px，输入和按钮 9px，状态徽章使用胶囊形；不把所有东西做成同一个圆角卡片。

### 动效

- 页面切换只做 180ms 的透明度和 3px 位移，告诉用户上下文已经变化。
- 按钮反馈 120ms；按下时轻微下沉；不对每一行做持续浮动。
- 记忆图示保留呼吸和交互后的恢复，但只在图谱空闲时发生，尊重减少动态效果设置。
- 导入、检查、更新、重建使用进度和阶段文本，动效服务于状态，不用装饰性波纹遮挡信息。

## 预览如何对应现有功能

- 预览中的 `记忆仓库 / 记忆图示 / 技能仓库 / 安全中心 / 设置选项` 对应 `MainWindow` 的现有页面入口。
- 双击记忆条目、技能行和安全行的详情窗口在预览中用聚焦态和操作栏表达，后续实现时保留现有非模态窗口行为。
- `路线 A · 离线` 与 `路线 B · AI` 明确并列，遵守现有安全检查的显式线路选择要求。
- `D:\MSH`、`复制注入提示词`、`投递箱`、`归纳整理`、`整理日报`、`导入记忆技能库…`、`关于 123 MSHub` 等文案保持现有产品语义；样本列表用于审阅密度与层级，不代表当前仓库的实时完整数据。
- 预览包含亮色和暗色两套主题，使用右上角主题按钮切换，也支持 `?page=memory&theme=dark` 直接打开指定状态。

## 评审重点

请优先看以下几个问题：

1. 记忆页是否能在 3 秒内判断“我该搜索、创建、编辑还是处理投递箱”。
2. 技能页的长名称、来源、中文备注、安全状态和更新时间是否比现版更容易扫读。
3. 安全中心是否让“尚未检查”和“0 项命中”产生足够明显的差异。
4. 图示页的图形是否保持主角地位，同时能找到搜索、复位、共同标签边、设置和打开条目的入口。
5. 设置页是否仍然保留完整能力，但不再像一张没有段落的长表单。
6. 皇家蓝和玻璃动效是否仍然像 123mshub，而不是换成一个无关的通用 SaaS 主题。

本轮得到确认后，下一轮才会把选定的 token、页面布局和控件状态写回 PySide6 原生界面，并按页面逐项保留现有功能、路由、异步任务和真实文案。
