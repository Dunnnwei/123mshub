# v1.12.1 实施与验收计划

日期：2026-11-03。基线：v1.12.0 / 16956f8a3b85eb90d6df8d68d98d5fcba4bfd8f9。

## 用户范围

1. 记忆和技能列表主动切换排序后立即展示新排序的第一项。
2. 查验同步盘文件已到达却未显示的问题；只修复确认存在的启动遗漏，不增加常驻文件监视或定时扫描。
3. 发布 v1.12.1 补丁及兼容在线更新的 Windows 完整包。

## 检查结论与实现

- 技能页的排序重建会恢复旧选中行并滚到中间。主动点击排序表头后改为回到顶部；普通刷新和编辑保存仍保留原定位。勾选身份与当前编辑不变。
- 记忆页此前使用排序下拉框，列头只是标签。将名称、标签、分类、来源、时间列头接入立即排序，同列再次点击反向；原下拉框继续可用。使用当前内存中的列表立即排序，异步读取返回时仍遵循当前排序。保持勾选、筛选和未保存编辑。
- 原生启动 `MainWindow.startup → MemoryFacade.heal → MemoryService.heal` 仅处理记忆。`SkillRepository.list` 仅在数据库空时恢复同步条目；网页 API 的后台技能对账没有接入原生启动。启动时复用手动“重新识别已同步条目”的对账操作，放入已有串行任务队列，完成后通知各列表刷新，失败保留任务详情与重试入口。每个窗口仅启动一次，不重复扫描。
- 保留现有仓库布局、配置、HAUI 资源、原有数据操作及升级校验机制。

## 验收矩阵

| 场景 | 预期证据 |
| --- | --- |
| 技能各可排序列升序/降序，列表滚到底部 | 点击后滚动位置为顶部且首项可见；勾选身份不丢 |
| 记忆各列与原排序下拉框 | 排序正确、立即到顶部；异步刷新保持排序 |
| 记忆编辑未保存、多选、语言切换、空结果 | 无意外确认、编辑不丢、选中身份不串行、表头状态正确 |
| 已有本地数据库，启动前只同步新技能目录 | 无需手动识别，后台完成后技能与安全列表出现新条目 |
| 启动结束后才同步目录 | 不自动常驻扫描；手动识别或下一次启动可恢复 |
| 启动识别失败或重复调用启动入口 | 失败不阻塞界面；任务可查看，重复调用不重复提交 |
| 发布 | 全量 Python 回归、实际 Windows 冻结程序 UI 检查、包内容/版本/哈希校验、Defender 扫描 |
| 在线更新 | GitHub latest 指向 v1.12.1，固定格式 ZIP 与 SHA256SUMS 可读取，公开下载摘要与本地一致 |
