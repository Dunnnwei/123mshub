## 三、审查重点(按优先级)

### 重点 1:upgrader.py 深审(零审查记录的新模块,安全敏感)

以攻击者视角逐函数过 `src/mshub/native/upgrader.py` 及其调用链(设置页「检查更新」→
确认 → jobs 后台下载覆盖 → 提示重启):

- 下载链路:releases/latest 元数据被伪造时的利用面;mirror / proxy / token 失效路径;
  HTTP 错误码处理;下载中断/半包后重试的幂等性
- zip 解压:`_extract_zip_safely` 防 zip-slip 是否完备(绝对路径、`..`、超长路径、
  符号链接条目、大小写变体);`pick_asset` 认 zip 的文件名规则可否被构造资产名绕过
- 覆盖安装:`.mshub-old` 改名逻辑——中途失败会不会留下半新半旧的安装?残留会不会
  无限堆积?`cleanup_old` 启动清理会不会误删用户文件?
- 失败路径:每一步失败后用户看到什么、重试是否安全、会不会把好版本覆盖成坏版本

### 重点 2:v1.8.1 + v1.9.0 增量全过(git diff 3e0b975..HEAD)

- 批量删除 / 彻底删除(hard 参数直达 rmtree、记忆不进 trash):误删、路径逃逸、
