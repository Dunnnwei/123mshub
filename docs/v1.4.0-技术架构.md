# 123 MSHub v1.4.0 技术架构

> 状态：执行基线（native/v2）
> 目标版本：v1.4.0 原生壳 MVP
> 依据：《v1.4.0-原生化总体方案.md》与《v1.4.0-迭代历史与避坑清单.md》
> 技术路线：PySide6 + Qt WebEngine 图谱岛
> 本文件是实现边界和验收口径；实现过程如果发现必须改变这里的约束，先追加决策记录，再改代码。

## 1. 架构结论

v1.4.0 使用一个 Python 进程承载原生桌面窗口。业务核心继续使用 src/mshub/ 的现有模块，原生代码只放在 src/mshub/native/ 适配层。主界面由 Qt Widgets 绘制，只有记忆图谱保留为本地静态页面，通过 Qt WebChannel 与 Python 进程通信。

程序启动后不创建 FastAPI、uvicorn、WebView2 或任何 TCP 监听。所有业务调用都是进程内 Python 函数调用；图谱页面使用 QUrl.fromLocalFile() 加载，页面资源从程序目录读取，数据通过 QObject bridge 注入。

这里的“兼容”以当前 v1.3.3 代码实际读写位置为准：ConfigStore 的 SERVICE_NAME 是 mshub，因此默认配置目录是 %APPDATA%/mshub。总体方案文字中出现的 %APPDATA%/123mshub 是产品命名目标，但不能让原生线另建目录而丢掉旧配置；如果未来要改名，必须做显式迁移并保留回滚。

架构优先级固定为：

1. 仓库文件和现有业务核心的兼容性；
2. UI 线程可交互，慢操作可取消或至少可观察；
3. 无端口、无云端、无管理员权限、无未知网络访问；
4. 与 v1.3.3 的记忆列表、编辑、软删除和图谱行为一致；
5. 视觉接近 123UI v4.2，细节不足时优先保持信息层级与可读性。

## 3. 运行时分层

    用户输入/拖放
       ↓
    PySide6 QMainWindow
       ↓
    Native App State
       ↓
    Native Facades
       ↓
    src/mshub 业务核心
       ↓
    仓库文件 / SQLite / .meta

记忆图谱是唯一的 web 岛：

    QMainWindow → QWebEngineView
    QWebEngineView ↔ QWebChannel QObject bridge
    QWebEngineView → 本地 index.html / graph.js / graph.css
    graph.js → sigma + graphology + FA2 本地资源

### 3.1 进程模型

- 一个主进程、一个 QApplication；
- 一个主 UI 线程，只做窗口、模型更新、轻量格式化；
- 一个 QThreadPool 执行文件扫描、记忆列表读取、编辑保存、软删除、图谱数据生成和后续导入任务；
- 不启动 HTTP 服务、不启动子服务、不创建常驻 worker 进程；
- 关闭主窗口时先停止接受新任务，等待可安全收尾的任务，然后退出 Qt 事件循环；不能留下驻留的 Python 进程。

### 3.2 线程模型

所有耗时调用走 TaskRunner：

    submit(callable, args)
      → QRunnable 在 QThreadPool 执行
      → WorkerSignals.finished(result)
      → WorkerSignals.failed(error)
      → WorkerSignals.progress(value, message)
      → 主线程更新 AppState / Qt Model

约束：

- worker 不碰 QWidget、QAbstractItemModel 或 QWebEngineView；
- worker 不直接发 Toast；错误通过 signal 回到主线程；
- 任务带递增 request_id，只接受当前请求的结果，防止快速搜索/切页的旧响应覆盖新状态；
- 视图销毁时取消或失效对应 request_id，清理定时器和 signal 连接；
- 批操作逐条容错，汇总成功/失败数量，禁止宽 except Exception 静默吞错；
- 文件写入继续使用业务核心的原子写和 syncsafe 纪律。

    ├── memory_facade.py            # MemoryService 的 Qt 友好适配
    ├── config_facade.py            # ConfigStore 的草稿/保存适配
    ├── graph_bridge.py             # QWebChannel QObject bridge
    ├── views/
    │   ├── sidebar.py

mshub.native 是唯一允许依赖 Qt 的包。src/mshub 业务模块不能反向 import mshub.native，从而保持服务层、CLI 和原生 UI 的依赖方向单向。

### 4.1 入口与配置隔离

- mshub.native:main 为开发入口；
- python -m mshub.native 与 PyInstaller 入口调用同一个 main()；
- 使用现有 ConfigStore，配置目录仍为 %APPDATA%/mshub/；
- Qt WebEngine profile 放在 %APPDATA%/mshub/web-profile/，仅保存图谱页面的本地设置和缓存，不保存业务事实源；
- 进程启动参数支持 --repo <path> 作为调试/文件关联入口；没有参数时读已有配置；
- 不把 token、AI key 写入日志、QSettings 或明文配置；凭据继续走现有 keyring 适配。

### 4.2 依赖策略

pyproject.toml 增加可选组：

    native = ["PySide6>=6.8,<7"]
    release = ["pyinstaller>=6.16,<7"]

PySide6 的 QtWebEngine、QtWebChannel 和平台插件随 onedir 一起打包。开发机没有 native extra 时，服务层和 CLI 仍可正常运行；启动原生入口时给出明确的依赖提示，不做隐式联网安装。

前端图谱依赖继续使用仓库已有的 sigma、graphology、graphology-layout-forceatlas2 版本，构建时打成一个本地 graph.js。图谱岛不引用 CDN、远程字体、远程图片或任何 http:// / https:// 资源。

## 6. 图谱 web 岛

### 6.1 加载方式

GraphView 创建持久化 QWebEngineProfile：

- offTheRecord=False；
- setPersistentStoragePath(%APPDATA%/mshub/web-profile)；
- QWebEnginePage.setWebChannel(channel)；
- setUrl(QUrl.fromLocalFile(native/graph/index.html))；
- 拦截导航，拒绝非本地 URL；
- 开发/测试时关闭远程调试和自动打开开发者工具。

QWebEngineView 不在 MainWindow 构造时创建。主窗只放轻量占位页，第一次点击“记忆图示”时才创建 QWebEngineProfile、QWebEnginePage 和 QWebEngineView；这样冷启动测量不把 Chromium 初始化算进首个可交互窗口之前的路径。

页面只加载本地 HTML、JS、CSS 和 qrc:///qtwebchannel/qwebchannel.js。业务数据不通过 URL 参数、不通过临时 HTTP 服务传输。

### 6.2 Bridge 协议

Python bridge 是 QObject，页面端只依赖以下接口：

    getGraph(kinds: string) -> JSON 字符串
    openMemory(name: string) -> signal openMemoryRequested(name)
    getTheme() -> JSON
    readGraphSettings() -> JSON
    writeGraphSettings(payload: JSON) -> void

- getGraph("link") 与现有 /api/memory/graph?kinds=link 语义一致；
- getGraph("link,tag") 保留共同标签边；
- 返回值字段保持 nodes、edges、memory_root；
- GraphView 创建时先用 QThreadPool 预热 `link` 图谱并缓存到 bridge；WebChannel 首次调用如果缓存已到位只做序列化，缓存未到位时才在 Qt 主线程做一次同步兜底。这样 MVP 不改变 QWebChannel 的回调协议，同时把常规打开路径放到后台；进入 v1.5.0 的大图性能门槛前，将把 cache-miss 也改成信号式异步协议。
- 页面端沿用 v1.3.3 的确定性初始位置、FA2 worker、悬停一度聚焦、拖拽 reheat、搜索淡出保留、类型筛选、标签边和设置项；
- graphology-layout-forceatlas2 0.10.1 的 worker 实现本身把代码内联成 Blob URL。页面协议为 file:// 或 qrc:// 时仍先尝试 worker；如果 Chromium 拒绝 Blob worker 或 worker 初始化抛错，立即降级到有界的主线程同步 FA2（节点越多迭代次数越少），绝不为了绕过 CORS 启动 localhost 服务。降级时拖拽只做短批次 reheat，保持可用性并避免长时间占满 UI；
- Sigma 业务类型与渲染程序分离，显式映射所有 user/project/reference/feedback 到圆形渲染程序；
- 透明度不用 WebGL rgba 直接混合，按实际背景色计算不透明混合色；
- 页面销毁时杀掉 FA2 worker、清理定时器和事件监听；
- 图谱设置保存到持久 profile；如果 localStorage 不可用，回退到 bridge 的 ConfigStore 存储。

### 6.3 安全边界

图谱岛是受信任的本地资源，不执行仓库 markdown 中的脚本，不把仓库内容当 HTML 插入。标签、标题和 tooltip 通过 DOM text 或 Sigma 属性传递。任何非本地导航一律拒绝。

## 7. 数据兼容与错误处理

- 启动首先调用现有 MemoryService.heal()/只读列表路径，失败步骤单独计数；不能因为一个坏条目让整个列表白屏；
- 所有文本读写接受 UTF-8 BOM；
- 路径只在目标仓库和已配置的 memory root 内，symlink 不跟随；
- 条目名先 NFKC 归一化并经过现有 validate_name；
- 软删除使用核心实现，原生 UI 只确认和展示回收路径；
- 旧仓库无需迁移；原生版写出的 markdown、索引、.meta 和 SQLite 必须被 v1.3.x 直接打开；
- UI 错误显示操作、原因和下一步，不显示 traceback；traceback 写入本地任务日志并保留原始异常用于测试；
- 无法识别的数据按条目隔离，继续加载其余条目，并在状态栏显示失败数。

## 8. 打包、启动和安全姿态

### 8.1 开发启动

    $env:PYTHONPATH = "src"
    .\.venv\Scripts\python.exe -m mshub.native

测试使用 QT_QPA_PLATFORM=offscreen，不依赖桌面可见窗口。

### 8.2 onedir 发布

PyInstaller 使用 onedir，不使用 onefile：

- 主 exe、Qt6 DLL、QtWebEngineProcess、resources、translations、图谱岛静态资源全部在目录内；
- 入口为 mshub.native.__main__；
- PyInstaller spec 显式收集 PySide6.QtWebEngineCore/Widgets、QtWebEngineProcess.exe、Qt6WebEngine*.dll、resources 和 translations，并在发布前以干净目录启动一次图谱页；缺一项都算打包失败；
- 不注册服务、不请求管理员、不写启动项、不自启动；
- 发布物附 SHA-256；
- netstat -ano 在运行期间不能出现新增监听端口；
- 冷启动从进程启动到主窗可交互目标 ≤3 秒，业务自愈/索引重建在后台；
- 内存口径拆开记录：主 Python/Qt 进程常驻目标 ≤200MB；图谱页打开后 Chromium renderer、GPU 和 WebEngine profile 的基线/峰值单独记录，不把后者偷偷并入主进程数字；报告同时给出两组 PID 的工作集和峰值。
- onedir 包体积单独记录，预期会比旧 26MB 级 EXE 大很多。当前 PySide6 6.11.2 + QtWebEngine 的实测基线为 363.04 MB（保留完整资源）/ 345.81 MB（移除调试包、开发者工具和未用语言包后）；`Qt6WebEngineCore.dll` 本身约 194 MB。这是 Chromium 的发布成本，不能把体积增加误报为功能回归；升级 Qt 时必须重新实测并更新报告。

### 8.3 文件关联预留

v1.4.0 只定义 --repo 参数和 mshubrepo 入口协议；真正注册 Windows 文件关联、通知、托盘和拖放能力放在 v1.6.0，避免 MVP 里伪造完成状态。

### 8.4 单实例与退出

使用配置目录中的 QLockFile 做单实例锁。第二次启动只提示一次并退出，不重试驻留；锁文件是 Windows 命名对象/文件锁，不创建 TCP 监听，因此 netstat 零监听验收不受影响。关闭窗口后显式等待短任务并释放锁，验收用 PID 检查没有残留进程。

## 11. 变更规则

- 选择 PySide6 是方案 §4.1 的默认路线，不构成偏离；
- 采用本地静态 graph island、QWebChannel、QThreadPool 和 onedir 是本文件的固定实现；
- 如果要换 UI 栈、重新修改 src/mshub 核心语义、引入 TCP 服务、使用 CDN 或改变数据格式，必须先新增 docs/v1.4.0-技术选型决策记录.md，列出兼容性、性能、安全和回滚论证，得到用户确认后再执行；
