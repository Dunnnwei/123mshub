## 2. 坑清单（按类，每条：现象 → 根因 → 纪律）

### A. Windows / 编码 / 同步盘

1. **Defender 瞬时锁**：更新技能时 `PermissionError` 一次即废——实时扫描新建文件的独占句柄
   撞上突发写入。**纪律：一切落盘走 syncsafe 五档退避（0.2→3.2s），原生版不许裸写文件。**
2. **同步盘排除点开头文件**：曾致 91 份清单全丢（`.manifest.json` 被 fn-sync 整类过滤）。
   纪律：进同步盘的文件名禁用点开头（`_manifest.json`）；`.meta\`（SQLite）永不进同步盘；
   技能内点文件走 `_dot_/` 容器运输（`.github/workflows/ci.yml` → `_dot_/dot.github/...`）。
3. **空清单事故**：分机同步未完成时识别，写出的空清单回传覆盖总机好清单，69/90 被清空。
   纪律：没有任何内容文件的目录一律跳过不写清单；「空清单+目录有内容」=自愈重建信号。
4. **PowerShell 中文**：内嵌脚本必须 UTF-8 **带 BOM**，否则乱码；PS5.1 的中文 JSON 响应
   要按原始字节 UTF-8 解。
5. **GBK 三坑**：AI 供应商预设名勿用中文；zip 内中文文件名在非中文 locale 解压乱码
   （发布物资产名全 ASCII）；控制台 subprocess 一律 `encoding="utf-8", errors="replace"`、
   git 加 `core.quotepath=false`。
6. **文件名净化**：拦 Windows 保留名（CON/PRN…）、非法字符、点开头；NFKC 归一化先行
   （全角「ＭＳ Ｈｕｂ」→ `ms-hub`）。
7. **BOM 容忍**：读条目/索引/导入源一律 `utf-8-sig`——Windows 编辑器默认写 BOM，
   不容忍则 frontmatter 认不出、索引误重建。

### B. 进程 / 并发

1. **双开连环弹窗**：端口被占→重试→驻留→再弹（用户桌面事故×2）。纪律：占用检测
   提示一次即退出；原生版此问题连根不存在，但「检测-提示-退出」模式保留。
2. **关窗僵尸进程**：WebView2 线程偶发不随主线程退出→占端口→次日连环弹。纪律：关窗
   强制退出进程；原生版换栈后仍要验证「关窗=进程必死」。
3. **测试 EXE 用进程内/单发**：验收脚本反复起实例=用户桌面弹窗轰炸。
4. **请求竞态**：快速切筛选时先发后至的响应覆盖最新选择。纪律：防抖 + 请求序号
   （只认最新一次）；列表类 watch 一律防抖 300ms。
5. **组件销毁后回调仍触发**：定时器/异步回调必须挂 onUnmounted 清理。

### C. 数据 / 幂等（ importer 与对账的血泪）

1. **宽 `except Exception` 静默吞错**：`_same_entry` 引用未导入函数，异常被吞、幂等失效
   而表面正常。纪律：except 块要么处理要么记日志，禁止裸吞；import 错误在 CI 静态检查。
2. **单条脏数据拖垮整批**：notes 里一个中文文件名让整个列表对账抛错。纪律：按条目
   try/except + continue，坏件隔离留待自愈，批操作永不全废。
3. **重名避让无限累积**：`-2`、`-3`…重复导入越攒越多。纪律：避让前做内容比对
   （忽略 name 字段），相同即跳过——导入幂等是硬承诺（60 记忆+255 技能零重复已验证）。
4. **copytree 中途失败残留**：残目录使 `target.exists()` 命中→永远 skipped 无法修复。
   纪律：失败分支清理目标目录，或临时目录+原子改名。
5. **纯中文标题 sanitize 成空串**：非 ASCII 全剥→保存按钮禁用/后端 400。纪律：空结果
   走 `slug_from_title` 兜底（日期+短哈希），且哈希用 **sha256**（内置 `hash()` 受
   PYTHONHASHSEED 影响，跨进程不稳定，会破坏条目名作为长期标识）。
6. **派生物写盘纪律**：index.json / MEMORY.md 重建时「实质没变→一个字节不写」
   （比对忽略时间戳），写=临时文件+`os.replace` 原子替换。否则同步盘永无宁日。
7. **双写顺序**：SQLite 与文件双写时**先文件后库**（文件是事实源）。
8. **跨机回填**：manifest=跨机事实源，本机 SQLite 只是缓存；编辑/标签/翻译/检查结论
   都要落 manifest 才能跨机传播（最后写 manifest 者赢，幂等）。

### D. 前端 / 图谱 web 岛（原生版直接相关）

1. **sigma WebGL 无真 alpha**：渲染器预乘混合 `blendFunc(ONE, ONE_MINUS_SRC_ALPHA)` 但
   颜色管线不预乘 → `rgba(...,0.10)` 渲染成**接近不透明的亮灰**，悬停淡出完全反向。
   纪律：淡出一律 `blendToBackground()` 向实测底色混合的**不透明 hex**（节点 0.10 /
   边 0.12 / 焦点边 0.45 / 悬停邻边=节点类型色 0.60）；底色 `getComputedStyle` 实测，
   随亮暗主题重算。**图谱岛移植时这条原样带走。**
2. **节点业务类型 ≠ 渲染程序名**：Sigma 把节点 `type` 属性当 WebGL 程序键查
   （`could not find program for node type "project"` → 白屏）。纪律：语义类型与渲染
   类型分离，`nodeProgramClasses` 显式映射。
3. **WebView 设置持久化**：pywebview 默认 private mode → localStorage 重启即丢
   （v1.3.3 修：`private_mode=False` + 持久 storage_path）。**图谱岛的 QWebEngineView
   同理：必须用持久 profile，图谱设置才能记住。**
4. **布局与交互契约**（v1.3.3 已达标，勿倒退）：FA2 跑 worker；停稳后拖节点要 reheat；
   筛选/搜索只 refresh 不重跑物理；`hideEdgesOnMove` 仅边数 >8000 开；边有权重
   （双链 2/标签 0.5）才让弹簧滑杆有意义；初始位置确定性伪随机（同数据同布局）。
5. **markdown 渲染顺序**：先抽代码片段为占位符再跑其余规则，否则代码内 `**`、链接
   被二次解析。
6. **状态生命周期**：弹窗重开要 reset；watch 要覆盖 entry/mode 变化（不只 open 跳变）；
   重名校验用全量列表不用过滤后列表；AI 补全只填空位不覆盖用户输入。

### E. 打包 / 发布 / 网络

1. **EXE 冷启动**：onefile 每次解压到临时目录，大仓库 health 数十秒不应答。原生版
   用 onedir；冷启动 ≤3s 是验收项。
2. **未签名 EXE**：SmartScreen「未知发布者」提示消不掉（根治=代码签名证书）；
   发布附 SHA256、README 写「仍要运行」指引、发布前 VirusTotal 留档。
3. **git 令牌格式**：git HTTP 通道只认 `basic base64(x-access-token:<token>)`，
   Bearer 必失败（REST 端点两者皆可）。
4. **代理劫持**：subprocess 会继承残留的代理环境变量（127.0.0.1 死代理劫持 git）。
   纪律：拉取前清空继承代理变量，程序设置是唯一权威。
5. **任务面板删除要服务端真删**：前端藏=重开复活。

### F. 测试纪律

1. **测试必须隔离系统钥匙串**：曾把用户真实 AI key 覆盖掉（conftest 自动内存副本）。
2. **`assert x or True` 恒真断言**：写了等于没写，逐条审查测试的有效性。
3. **真实 agent 实测是发布门禁**：暗号全链路（粘贴提示词→读记忆→用技能→投递→收编
   →下轮读到新记忆）不能只测 API。
4. **性能冒烟进测试套**：3000 节点 6000 边布局必须每次跑，防性能悄悄回退。

## 3. 不能丢的细节功能清单（重写对照表）

> 这些功能大多「看不见」，丢一个用户不会立刻发现，但出事就是数据级事故。
> 原生化每个里程碑验收时逐项打勾。

### 3.1 仓库即接口（对 agent 的文件契约，与 UI 技术无关，**必须字节级保留**）

- [ ] `memory\MEMORY.md` 索引格式：type 分组、组内 name 排序、行=「[标题](notes/xx.md) — 描述」；
- [ ] `memory\notes\*.md`：frontmatter = name/title/description/type/tags/created/updated/source；
- [ ] `memory\inbox\` = agent 唯一可写区；投递格式（kebab-case 文件名 + frontmatter 规范）；
- [ ] `_共享技能库使用说明.md`：相对表述（"本文件所在目录即库根"），任意挂载路径成立；
- [ ] `index.json` 在库根（未装程序的机器也要能查清单）；
- [ ] `_manifest.json` 运输视图（点文件记容器路径；物化产物与 git.bundle 不入册）；
- [ ] `_dot_/` 容器与收敛规则（真实存在无容器→收编；容器较新→覆盖物化）；
- [ ] 项目旁 `git.bundle` + 「有 bundle 没 .git」自动还原并指回真实 origin；
- [ ] `.meta\` 本机私有（SQLite/backups/trash/staging/memory-trash/conflicts），同步应排除。

### 3.2 注入提示词契约（产品灵魂，逐字节一致）

- [ ] 模板五段：记忆读取 / 技能库使用 / 记忆投递 / 安全纪律 / 连通暗号；
- [ ] 暗号精确匹配「天王盖地虎」→ 只回一行「AI镇河妖！暗号对齐，123mshub已接入，
      当前仓库拥有X条记忆，X项技能。」（X=生成时刻实数清点）；
- [ ] 仓库触发词（总机/mshub/本地仓库/记忆仓库→非任务也先读索引）；
- [ ] 值守整理提示词（值守权限语义）与「指定技能提示词」（读说明文件模式）。

### 3.3 隐性行为

- [ ] 软删除：技能→`.meta\trash\`、记忆→`.meta\memory-trash\`；
- [ ] 冲突副本三策略：索引副本直接清（可重建）、notes 副本隔离+人工裁决提示、
      inbox 副本隔离留档；
- [ ] 启动对账并入自愈总编排，逐步容错（单步失败只计错误）；
- [ ] inbox 收编预览跑 md 注入规则组→红条警告（**不阻断、不自动清洗**，人裁决）；
- [ ] 导入边界：只写本仓库、来源绝不写、排除 node_modules/.git/.meta、**symlink 全程
      不跟随（防目录循环与越界，Engramory 0.3.3 教训）**、扫描上限 20k md / 单条 512KB /
      技能 >500MB 拒绝、幂等；
- [ ] 更新技能时上游备注未变沿用旧译文，变了清空待重翻（description_zh 全链路）；
- [ ] 本地自研条目：更新/查版本置灰 + 原因提示；无清单旧技能自愈生成可恢复清单；
- [ ] (name, library) 复合键定位；跨库同名合法；编辑信息身份与归属分离；
- [ ] 批量操作逐条容错（单条失败不断整批，汇总「已 N 失败 M」）；
- [ ] keyring 存凭据，明文零落盘；设置下发仅打码凭据（头尾各 4 位）；
- [ ] 技能列表开屏秒出（列表接口不做全量哈希，详情按需）。

### 3.4 Engramory 谱系与上游纪律（记忆结构的来源）

记忆库的结构设定借鉴自 [Engramory](https://github.com/tinqiao-oss/engramory)
（MIT，抖音 @李云放而已 的开源项目），README 致谢保持。**本次重建的关联**：它的核心
结构就是 §3.1 文件契约本身——重建时按 §3.1 字节级保留即等于保留这套设定；另有几条
从它上游 CHANGELOG 定向吸收的纪律，出处在此记清，防止重写时当成无本之木删掉：

- [ ] **条目 + 常读索引 + inbox 模型、四类型词汇（user/feedback/project/reference）**
      ——即 §3.1 契约（「记忆是一套纪律，不是一个数据库」）；
- [ ] **整理纪律进注入提示词**：写前查重、更新而非重复、不存代码已记录的内容、
      密钥只记位置不记值——属 §3.2 逐字节契约的一部分；
- [ ] **索引上限健康线**：宿主 agent 通常只加载索引前 200 行 / 25KB，本产品以
      150 行 / 20KB 为健康线在 tidy 盘点中提示精简（Engramory 索引纪律）；
- [ ] **symlink 不跟随**（0.3.3）、**BOM 容忍**（0.1.12）、**任务边界判定 + 易变值
      规则**（0.10.1 / 0.6.1）——已分别落入 §3.3、§A7、§3.2。

两条备注：

1. **勘误（做介绍视频时注意）**：Engramory 官方没有「四层架构」「只读证据追溯」的
   说法——早期对比版本的宣传物料里出现过，来源存疑疑为幻觉，**致敬时只写上述可验证
   的借鉴点**；
2. 上游是活项目，重写期间可再查其 CHANGELOG 有无可吸收的新教训（v1.2.0 的
   BOM/symlink/NFKC 三条就是这么来的）。

## 4. 使用方式

1. v1.4.0 动工前通读本文 + 《v1.4.0-原生化总体方案.md》；
2. 每个里程碑（1.4.0/1.5.0/1.6.0/2.0.0）验收时：§2 六类坑逐类自问「我的实现里
   这个坑防了吗」，§3.1/3.2/3.3 逐项打勾；
3. 踩到新坑：修完必须回写本文（现象→根因→纪律三段式），这是两个项目延续下来的
   纪律——**坑清单只进不出，新坑不过夜**。
