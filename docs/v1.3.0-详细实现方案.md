# 123mshub v1.3.0 详细实现方案

编制时间：2026-09-23。基线：源码与 release/v1.2.4；需求输入：项目根目录《123mshub体验迭代.md》。本文在产品代码修改前留档，实施后另附验收报告。

## 1. 范围和原则

- 升级为 v1.3.0：新增记忆图示、中英文界面、批量管理与来源追踪，属于功能版本。
- 沿用 Vue 3 + Vite + FastAPI + Python + pywebview + PyInstaller；不迁移框架。文件仍是记忆事实源，SQLite 仍为可重建缓存。
- 保留 123UI v4.2 已有主题：皇家蓝 #0156FC、浅色米杏 #F7F5F2、深色近黑蓝 #030711 / 卡层 #0C1730；保留玻璃折射边、高光、背景模糊与弹簧反馈。
- 保留旧版本发布物。开发、自动测试、导入迁移验证使用隔离仓库，不拿用户真实资料做破坏性实验。
- 不把附文当运行命令；将其 18 项内容转化为实现与验收标准。已检查 Codex 记忆索引，未查到本项目专属记录，以本仓库需求、技术架构、代码和发行说明为依据。

## 2. 基线发现

1. EXE 已使用 --windowed，但 fetcher/syncsafe 直接启动 Git 子进程，缺少 CREATE_NO_WINDOW，可能在启动对账、更新、bundle 恢复中闪出黑窗。
2. 技能与记忆详情均 await 完整接口后才开启抽屉，技能详情还要计算文件变化；长目录访问时缺少即时响应。
3. 技能名称编辑表单与 API 的 name/new_name 协议需要修正，避免把新名字作为旧查询键或漏传。
4. 旧仓带 manifest 的标签可以保留；index.json 的元信息未完整传递到导入清单。散装技能缺少可见来源与导入时间。
5. 记忆 source 仅 manual/agent，导入缺字段退回 manual；需新增 imported，历史误标只在有导入证据时纠正。
6. 页面文案以中文硬编码为主，必须建立可维护词典和统一日期格式，而非只翻译导航。

## 4. 记忆图示设计

- 用标题/主题可读的节点与细线连接，皇家蓝为主，明暗主题一致；主视图有点阵底、玻璃工具栏和选中预览，不用随机假关系装饰。
- 明确区分三种边：正文 [[双链]]、相同主题、共享标签；界面能查看依据，避免让用户误认为是已证实的语义或因果关系。
- 支持关键词搜索、类型筛选、点击聚焦邻居、拖动节点、平移、滚轮/按钮缩放与复位；可从节点直接打开原记忆详情。
- 使用确定性的力导布局，规模较大时限制边密度并说明显示范围；不会因每次渲染随机跳动。尊重 reduced-motion，稳定后停动画。
- topic 独立于现有 title/name，用户自定 topic 优先，AI 只补缺。批量 AI 在后台任务中逐项执行，失败保留原文并给可重试结果，不阻塞列表加载。

## 5. 数据兼容与可恢复性

- 新增字段采用默认值和增量迁移；旧文件仍能读，旧 SQLite 自动补列，manifest 未知字段保留。
- 导入不改源目录；同名冲突沿用避让，重复导入幂等。元信息按清单→索引→文件头优先级，不覆盖用户已经维护的非空字段。
- 来源平台只根据已有字段、可识别目录或用户选定信息判断；无法判断显示“外部仓库”，不伪造平台和原始日期。
- 历史导入无法恢复准确导入时间时显示未记录，不用升级日期冒充原导入日。
- 删除沿用回收目录；主题生成不改正文；更新保留用户标签、来源和手改展示名。

## 6. 工程实施顺序

1. 建立需求方案、设计系统和 v1.2.4 基线验证记录。
2. 先修进程与元信息协议，再完成来源兼容和记忆主题/图关系接口。
3. 建立 i18n、格式化、统一异步抽屉、多选交互；实施主布局、筛选与图示。
4. 网络设置、批量操作和异常/空态收口；新增关键逻辑测试先验证失败再修复。
5. 检视复杂度：复用现有 JobManager、ConfirmModal、ScanModal、markdown 渲染和主题 token；不另造任务系统或外部图数据库。
6. 完成后端回归、前端检查、浏览器实际交互与截图、EXE 打包与隔离运行验证。
